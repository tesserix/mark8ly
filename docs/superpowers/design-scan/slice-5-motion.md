# Slice 5 — Animation Audit (mobile-admin)

Read-only motion audit of `apps/mobile-admin` (React Native + `react-native-reanimated` 4.3.1). Bar: Emil Kowalski craft, app standard = `Easing.bezier(0.22, 1, 0.36, 1)` / 220ms, established in `components/navigation/Dock.tsx` and `components/products/disclosure-motion.ts`.

Every custom `Animated.View` entering/exiting site in the app grep-matches to exactly four files: `Dock.tsx`, `disclosure-motion.ts`, `SectionDisclosure.tsx`, `VariantRow.tsx`. Everything else in scope is either a gorhom `BottomSheetModal` (spring-driven, third-party), a raw RN `<Modal>` (system-driven), `TouchableOpacity`'s built-in opacity fade, or code with no motion at all where some arguably should exist.

## Verdict by tier

### Feel-breaking regressions
None found. No `ease-in` on UI, no `scale(0)`/pop, no unjustified >300ms UI animation, no layout-prop (height/width/top/left) animation anywhere in the four custom motion sites. The app's actual Reanimated surface (Dock, disclosure/chevron, variant row) is small, disciplined, and already at the bar it sets for itself.

### Missed simplifications
- None — the existing motion code is already minimal (one shared easing/duration module, no redundant per-component reimplementation aside from the Dock duplicate noted below).

### Performance
- **[P3]** No GPU-cost issues found — every animated property across the four custom sites is `opacity` or `transform` (chevron `rotate`). Confirmed via source read, not just the grep.

### Interruptibility/timing
- **[P2]** `disclosure-motion.ts` / `SectionDisclosure.tsx` / `VariantRow.tsx` — symmetric 220ms enter/exit; collapse should be faster (~160-180ms). *(pre-identified, confirmed)*
- **[P3]** Cross-cutting `TouchableOpacity` note (see table) — symmetric native press fade, not a real defect, called out for completeness.

### Physicality/cohesion
- **[P2]** `SectionDisclosure.tsx` / `VariantRow.tsx` reveal is opacity-only; add a subtle 4-6px directional transform. *(pre-identified, confirmed)*
- **[P2]** `OptionBuilderSheet.tsx` chip add/remove — no entering/exiting/layout transition, abrupt reflow.
- **[P2]** Gorhom bottom sheet default spring/easing in `OptionBuilderSheet.tsx` + `CategoryPickerSheet.tsx` doesn't match the app's bezier/220ms convention (not broken — no bounce, reduced-motion already honored internally — pure cohesion polish).
- **[P3]** `CategoryPickerSheet.tsx` checkmark pop with no transition.
- **[P3]** `Dock.tsx` `ENTRANCE_EASING` duplicates `disclosure-motion.ts`'s `DISCLOSURE_EASING` instead of importing it — token-drift risk.

### Accessibility
- **[P2]** Four raw RN `<Modal>` instances (`StoreSelector`, `LinkAccountPrompt`, `ImageViewer`, `orders/[id].tsx`'s `InputModal`) have no explicit reduced-motion handling — uncertain severity, flagged for device feel-check rather than confirmed as broken (iOS may auto-soften; Android likely doesn't).
- No **[P0]** accessibility gaps found: every custom Reanimated `entering`/`exiting`/`useAnimatedStyle` site (`Dock.tsx`, `disclosure-motion.ts`, `SectionDisclosure.tsx`, `VariantRow.tsx`) correctly branches on `useReducedMotion()`, and `use-created-banner.ts:41` correctly gates `scrollTo({ animated: !reduceMotion })`. `@gorhom/bottom-sheet` (used by both sheets) independently honors system reduced motion via its own `useReducedMotion()` call (confirmed in `node_modules/@gorhom/bottom-sheet/lib/module/components/bottomSheet/BottomSheet.js:169-172`), so the two `BottomSheetModal` sites are not an accessibility gap either.

### Additional missed opportunities (not corrective, additive)
- **[P2]** `products/index.tsx`, `orders/index.tsx`, `customers/index.tsx` — spinner-to-list swap on every cold load has no crossfade.
- **[P2]** `CreateNextStepsBanner.tsx` dismiss has no exit transition; the scroll content jumps.
- **[P3]** `products/[id].tsx` Save → Saving… → Saved label swap has no transition (likely fine as-is; flagged for completeness).
